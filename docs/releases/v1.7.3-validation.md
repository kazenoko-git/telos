# v1.7.3 MLX post-training validation

MLX SFT batches now stage directly as int32 arrays. MLX DPO reuses individual
frozen-reference response scores across shuffled batches, within the configured
batch-equivalent cache budget. Cache identity includes prepared-record identity,
response kind and padded width; misses retain complete reference-forward batch
shapes. The cache is rebuilt after resume. Other backends retain their existing
collation and cache paths.

The MLX DPO loss also fixes an autodiff error: the previous abs/maximum
softplus expansion has zero derivative at zero preference margin, where policy
and reference normally agree at initialization. `logaddexp(0, -margin)` supplies
the correct derivative of -0.5. This intentionally changes the broken trajectory.
Both sides of the final performance comparison include the same loss fix.

The full local CPU/Metal suite passed **344 tests, with 7 skipped and zero
failures**, in 14.48 seconds. The focused suite passed 59 tests. The configured CI lint checks and Python
compilation passed locally. Checks cover the zero-margin derivative, extreme margins,
masking/padding, score-cache capacity and row reorder, full/LoRA/QLoRA updates,
BF16 masters, optimizer/reference/RNG/sampler state, compiled/eager paths and
interrupted/resumed execution with a rebuilt cache.

On Apple M5 Pro, MLX 0.32.2, paired synthetic runs of a 47,069,696-parameter model
measured **5.55% faster SFT** and **25.46% faster DPO** end to end. Each fresh process
performed 256 updates with batch size 4, sequence length 256, width 512, 14 layers,
BF16 weights, FP32 masters and 32 distinct repeated examples. Order was
baseline/candidate/candidate/baseline per workload; both pair orders improved.
Timing includes setup, compilation, logging and checkpoint export, with device
completion fences at both measurement boundaries. Peak MLX allocation was
unchanged at about 1901.8 MiB for SFT and 2330.2 MiB for DPO.

Final model, FP32 master, optimizer, reference and MLX RNG tensors matched bit for
bit in both candidate/baseline pairs; sampling state matched too. The baseline is
v1.7.2 plus only the zero-margin loss fix. Tests and these exact comparisons do not
prove numerical equality across all shapes/runtimes or long-run convergence.

See the [machine-readable results](v1.7.3-local-results.json) and the repository's
[full experiment report](../../reports/mlx_posttrain_2026-11-16/REPORT.md) for
commands, baseline patch, timing repetitions, source hashes and earlier diagnostics.
Short 8–17 second final trials, repetitive synthetic responses and example reuse
limit the performance claim. Cold caches, large datasets, changing widths and
other chips may yield much less improvement. There is no new trained-model
quality, physical CUDA/TPU or distributed hardware result in this release.

The built v1.7.3 wheel was installed into a fresh isolated environment and
verified to import from its installed site-packages, outside all source worktrees.
All 59 focused tests passed again from copied test files against that installed
wheel (16.93 seconds), using Python 3.13.14, MLX 0.32.2 and freshly resolved Torch
2.15.0. The wheel's bundled tokenizer, frozen document-suite manifest, case and
reference counts, new MLX staging module and native bridge source inclusion
passed integrity checks; the sdist includes these release documents. These are
packaging/compatibility checks, separate from the Torch 2.13.0 benchmark runtime.
