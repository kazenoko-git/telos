# Télos v1.8.0 validation

## Online GRPO

The trainer stores the log probabilities under the sampling policy at each sampled action. The objective uses completion tokens, including sampled EOS, and averages token losses within each completion. The frozen reference supplies the optional per-token KL term. Checkpoints are saved at rollout boundaries. Resume tests replayed parameters, optimizer state and sampler RNG on CPU full training, MLX BF16 full training, and MLX QLoRA. Tests also verify clipped gradients, mask alignment, mixed completion lengths, EOS handling, and uniform rewards within a group.

A CLI smoke run used a one-layer causal model with width 32 and a ten-token vocabulary. It trained on one prompt with an exact-match reward for a one-token answer. The run used 20 rollout batches, two groups of 16 completions per batch, two updates per batch, a learning rate of 0.01, and a reference KL weight of 0.02.

| Checkpoint | Probability of the verified answer |
| --- | ---: |
| Starting model | 10.14% |
| CPU GRPO | 98.87% |
| MLX GRPO | 95.75% |

This checks that sampled verifiable rewards can change the policy in the intended direction on a synthetic task. Learning on real datasets and physical CUDA GRPO remain unverified.
