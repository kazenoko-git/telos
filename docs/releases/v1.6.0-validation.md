# v1.6.0 validation

Validated on 14 November 2026, on a clean release worktree based on remote main `38e5127`, retaining v1.5.1 through v1.5.5 training/resume changes. The original workspace contains unrelated tracked and untracked work and was not used as a package build input.

## Passed

- 18 new display tests: native alias deduplication, dual tracks, probe and audited-archive support, unscored/missing metrics, Reader evidence attachment, hostile HTML/script text, plain/off/NO_COLOR progress, a scored functional adapter fixture, saved-report CLI, and post-evaluation HTML export.
- Together with the existing benchmark-type tests: 31 passed.
- Repository CI lint selection: `uvx ruff check telos/ tests/ --select E9,F63,F7,F82`.
- Source distribution and wheel built successfully with `uv build`.
- Wheel archive contains report.html, report.css, report.js and logo.png.
- Isolated wheel installation reported version 1.6.0 and generated a Reader-1 notebook using its installed assets.
- Browser review: desktop and 390-pixel mobile layout; incorrect-case filter, search, expected/observed dialog, formula and Unicode evidence highlighting. Final 240-case report loaded with 162 correct results; JSON export downloaded and independently checked for 240 rows and the same score. Viewport override reset.
- Initial Reader evaluation: 40 model responses and 40 replay matches. Expanded evaluation: 240 model responses, 60 sampled replay matches, 240 exact-offset checks, no transport errors. These are diagnostic calls, not a model production-reliability claim.

## Broader regression limits

The broad test suite is not wholly green on this host. A first broad run stopped on the existing sandbox executor test: macOS sandbox-exec rejected launching the Python executable with Operation not permitted. The sandbox implementation is unchanged from the baseline; no policy was weakened.

A broader run excluding the sandbox execution test modules returned 194 passed, 3 skipped and 14 failed. Twelve failures came from the existing MLX accumulation experiment calling execute_mlx_training_step with an unsupported stage_profile argument. Two came from MLX gradient-checkpoint floating-point tolerances.

On a separate untouched worktree of remote main 38e5127, the same 12 accumulation failures and the FP32 gradient mismatch reproduced; the bfloat16 gradient case passed in that run, showing run-sensitive tolerance behavior. The relevant training, model, sandbox and experiment files are byte-identical between baseline and this release. These pre-existing issues are recorded here and were not folded into the display feature.

## Reproduction

```sh
pytest tests/test_eval_display.py tests/test_benchmark_types.py -q
uvx ruff check telos/ tests/ --select E9,F63,F7,F82
uv build
telos eval report reports/xerj_reader_2026-11-14/extended-run.json --cases reports/xerj_reader_2026-11-14/extended_cases.json --output evaluation.html
```
