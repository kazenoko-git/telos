# v1.7.2 validation and hardware reruns

## Fixes

- CUDA automatic precision excludes emulated BF16. T4 selects FP16 with scaling; native BF16 devices retain BF16. Pretraining profiles inspect every detected GPU. An explicit BF16 request retains its existing behavior.
- Before TPU topology detection and the SFT/DPO launcher, an explicit `TPU_ACCELERATOR_TYPE=v5e-1` normalizes host/process chip bounds to `1,1,1`. Conflicting worker/process counts or unusual bounds raise an error. Unknown and multi-chip accelerators are left unchanged. VM names are not treated as accelerator specifications.
- Portable PyTorch NF4 projections recompute the frozen dequantized weight during backward instead of retaining a dense matrix for input gradients. This trades computation for saved-tensor storage; it is not a fused kernel or a whole-model peak-memory claim.
- Post-training seeds Python and NumPy host RNGs as well as the backend RNG, before the resume session restores saved state. Fresh control processes now have reproducible host RNG checkpoints.

The XLA recomputation branch uses the [PyTorch/XLA checkpoint wrapper](https://github.com/pytorch/xla/blob/r2.9/torch_xla/utils/checkpoint.py), with its supported reentrant mode and XLA autocast/barrier handling.

## Local evidence

The [machine-readable local summary](v1.7.2-local-results.json) records test counts and the process/retention checks.

On Apple Silicon, the full CPU/Metal suite reports **330 passed, 7 skipped, zero failures**, including the unchanged MLX gradient tolerances. A separate process-based CPU run tests all four pretraining objectives plus SFT/DPO with full, LoRA and QLoRA training. Each control has a 12-update budget. The next process is terminated after its first atomic checkpoint, then restarted in a third process with the original budget.

The strict comparator checks the complete final checkpoint with identical paths/settings: all keys and container types, tensor shapes/dtypes/finiteness, optimizer moments, scaler fields, backend/host RNG, sampler and frozen DPO reference state. DPO invariant checks also compare the complete frozen reference against its initial model. It does not cast tensors, intersect keys, ignore fields or allow NaNs. Missing keys, changed optimizer moments, nonfinite values and shape/dtype differences have regression tests.

All ten CPU interruption/restart cases match exactly. LoRA checks all 12 frozen parameter/buffer leaves; QLoRA checks all 26, including quantization buffers, and checks nonzero adapter updates. A 512x512 CPU NF4 projection retains 1,048,576 dense-weight bytes without recomputation and zero with recomputation; loss and input gradients match exactly. This measures one projection's autograd retention, not total memory.

The benchmark uses the actual production training loop, verifies scheduler/global-step progress, finite losses/parameters and changed weights, and divides total completed input tokens by total synchronized elapsed time after five warmup updates. Setup/warmup-inclusive wall time is recorded separately. CUDA compile comparisons use identical workloads in fresh off/on/on/off processes, with aggregate token/time ratios and end-to-end time ratios reported separately.

## Correction to the v1.7.1 Antigravity report

The historical Colab artifacts remain unchanged in the validation worktree. They provide short, single-device execution evidence, not exhaustive validation:

| Historical claim | Audited status |
| --- | --- |
| CUDA 12M/50M and 3.15x compile training speed | Invalid as training performance evidence: the private loop never advances the scheduler and LR remains zero. Startup compilation was excluded. Rerun required. |
| XLA exact resume / optimizer invariants | Insufficient: the comparator only checked overlapping model weights, could falsely accept NaNs, and callers did not assert equality. Full-state rerun required. |
| Interrupted resume for all post-training modes | Incomplete: CUDA covered LoRA merged weights, and resumed completed controls rather than terminating an active process. |
| TPU standard launcher automatically handles the environment | Conditional: the script exported chip bounds externally. The failing probe injected different bounds; it did not establish the original unmodified environment. |
| All adapter invariants and distributed normalization | Incomplete: frozen CUDA checks covered embeddings only; XLA mainly checked artifact existence. One rank cannot prove cross-rank reductions. |
| QLoRA memory benefit validated on device | Not established: the historical measurements were general AR allocation figures, not matched NF4 profiling. |

No historical speedup is used to promote an optimization or change a default. Physical v1.7.2 CUDA/TPU execution, device-side export parity, multiple ranks, sustained convergence and representative-corpus performance remain pending. Existing local MLX export/gradient tests do not establish CUDA/TPU behavior.

## Reproduce on Colab

Use a fresh runtime for each accelerator, install a compatible Torch/XLA/libtpu stack for TPU, and install the v1.7.2 source or wheel. Do not force chip bounds in the harness. Set `TPU_ACCELERATOR_TYPE` only after confirming the actual allocation. The module verifies a real single device in an isolated probe before running training; launcher parents never initialize PJRT.

```sh
# CUDA: matched compile off/on/on/off, genuine interrupted restarts and NF4 probe
python -m telos.validation.hardware --hardware cuda --compile-abba --steps 20 --output /content/telos-v172-cuda

# Verified single-chip v5e allocation only
TPU_ACCELERATOR_TYPE=v5e-1 PJRT_DEVICE=TPU python -m telos.validation.hardware --hardware xla --steps 20 --output /content/telos-v172-xla
```

These are short correctness diagnostics with fixed tiny fixtures. They are not representative-corpus speed tests. Preserve the entire output directory: child commands/stdout/stderr, source/import/environment provenance, fixture hashes, checkpoints, dependency snapshot and results. A mismatch or child failure exits nonzero and writes `FAIL`; unsupported distributed/quality/whole-model-memory checks are explicitly listed as untested. The TPU run executes the NF4 saved-tensor diagnostic on CPU and labels it accordingly; CUDA also records actual allocator peaks for that projection. Larger models, real text, device-side export parity and multi-rank validation need separate matched experiments before making those claims.
