# v1.8.9 validation

This release lands incremental KV-cached GRPO rollouts with shared prompt prefill, sparse LM head projections for PyTorch SFT/MDLM and diffusion samplers, and KV-cached greedy decoding plus single-position `O(V)` probe evaluation across PyTorch and MLX.

## Verified Locally (PyTorch CPU)

- **Incremental KV-cache (`hidden_states_with_cache`) & shared-prefill GRPO rollouts (`telos/models/components.py`, `telos/models/transformer.py`, `telos/posttrain/grpo.py`, `telos/posttrain/trainer.py`):** Length-bucketed shared prompt prefill and `T=1` incremental decode measured **7.79× faster** (`624.75 ms → 80.24 ms`, 4-layer CPU, `B=2, G=4, prompt=64, new=32`) with `1.79e-6` max FP32 logit diff and exact MHA/GQA and ragged-prompt parity.
- **Sparse valid-only LM head in PyTorch SFT (`telos/posttrain/trainer.py`):** `_sft_loss_from_model` projects only `labels[:, 1:] != -100` hidden states, measuring **1.185×** E2E fwd+bwd (`131.63 ms → 111.06 ms`, 25% answer tokens) with **`0.0`** loss and gradient diff.
- **Sparse masked-only LM head in PyTorch MDLM (`telos/diffusion/mdlm.py`, `telos/training/trainer_pytorch.py`):** `mdlm_loss_from_model_pytorch` projects only masked positions and scatter-adds per-example CE, measuring **1.103×** E2E fwd+bwd (`131.80 ms → 119.46 ms`, 50% masked) with **`0.0`** loss and gradient diff.
- **Masked-only LM head in diffusion samplers (`telos/diffusion/sampler.py`):** Projects only masked positions in `MDLMSampler` and `MLXMDLMSampler`, measuring **1.055×** on CPU (`199.66 ms → 189.17 ms`) with exact token parity.
- **Evaluation decoding & probes (`telos/eval/runner.py`, `telos/eval/linguistic/evaluator.py`, `telos/eval/anticheat.py`):** Incremental KV-cache and tail-window stop checks in `_generate_greedy_completion` measured **5.10× faster** (`285.40 ms → 55.94 ms`, exact token parity); single-position / masked-span LM head projection with `O(V)` rank counting measured **1.27×** per probe (`3.96 ms → 3.12 ms`, exact rank match).

## Verified on Apple M5 Pro (`applegpu_g17s`, MLX 0.32.2)

Physical Metal test suite passed (**12 passed in 1.56s** via `.venv/bin/pytest -q tests/test_grpo.py tests/test_v189_optimizations.py`, including MLX BF16 full and MLX QLoRA GRPO rollout/resume replay) and benchmarks via `scratch/bench_v189_m5pro.py` recorded:

- **MLX KV-cached shared-prefill GRPO rollouts (14-layer BF16 49M, `B=4, G=4, prompt=64, max_new=32`):**
  - **Latency:** **75.26 ms** vs `246.10 ms` (**3.27× faster**).
  - **Peak GPU memory:** **202.09 MB** vs `488.70 MB` (**-58.6%**).
  - **Final-step logit parity:** `0.04688` max abs diff (within BF16 ULP across 14 layers).
- **`MLXMDLMSampler` masked-only head (`seq_len=128, prompt=32, 32 steps`):** `80.37 ms` / `156.56 MB` peak GPU memory.
- **Eliminated candidates:** `_foreach_*` `CautiousAdamW` on CPU (`0.84×` regression) and `MLXLoRALinear` scale-before-up-projection on M5 Pro (`1.018×`, unchanged `1250.34 MB` peak memory). Physical CUDA/TPU throughput remains pending hardware runs.
