# v1.7.7 validation — 2026-11-18

MLX pretraining enables compiled accumulation by default, alongside bounded async
accumulation. Disable with `--no-compiled-accumulation` or
`training.compiled_accumulation: false`. The memory planner is unchanged.
First microbatches use the existing loss/gradient path. Later microbatches compile
backward with accumulation; stage profiling bypasses this hook. Other backends
are unchanged.

The longer separate-process comparison completed four 768-update trials with
128 warmup updates excluded, at a fixed 3.2 GiB ceiling and planner-selected 1×64
batching. Compiled won forward/reverse by 22.6%/18.8%, with flat active MLX memory.
GPU clocks differed by 10–17%, exceeding the original matching gate.

Two complementary within-process replays then completed 1,536 updates each,
with 128 warmup updates excluded and randomized paired 32-update blocks. Async
was enabled throughout. Compiled won 43/44 adjacent pairs, with geometric gain
34.66%. Four pairs passed strict clock/thermal matching and all favored compiled,
with geometric gain 8.23%. Coverage was 3+1 pairs, below the planned 8 per trial
and 16 total. Clocks were observed, not locked. The release decision explicitly
accepts this evidence despite the failed strict-match coverage gate; the overall
percentage is not a universal or clock-isolated speed guarantee.

Active allocation stayed flat near 469 MiB; both workers completed without guard
failures under the user-selected +1 GiB swap-growth allowance. All 347 saved
numerical arrays matched bit for bit: 86 model, 86 FP32 master, 174 optimizer and
one MLX RNG array. Keys, shapes and dtypes matched; exported model file hashes
matched too. Structure JSON/host scalar metadata and arbitrary Python state are
outside this check. Portable analyses are in
`reports/mlx_compiled_release_2026-11-18/`.

This release also compiles accumulated-gradient scaling/clipping with the
optimizer update. The independent-reference tests cover changing clipping,
accumulation and learning rate for FP32/BF16 master paths. Its isolated boundary
probe took 18.9% less time; short full-training clock variation prevents a stable
end-to-end speed claim. See `reports/mlx_update_paths_2026-11-18.md`.

Validation uses the full local test suite, lint, and a clean committed-source
wheel/sdist build. Packaging checks verify version and bundled evaluation data.
No new CUDA/TPU hardware validation or long-run quality equivalence is claimed.
