Here is exactly how the checkpoint directory versioning and dynamic selection work in the codebase:

### 1. Checkpoint Directory Creation (in [`telos/training/trainer.py`](file:///Users/ivansamuel/Documents/Projects/telos/telos/training/trainer.py#L401-L410))

When a training run starts:
1. It reads the base target directory from the config (e.g. `checkpoints/phase_b_12m_1to25_mlx`).
2. **If the base directory does NOT exist yet (or is empty)**: It saves directly to `checkpoints/phase_b_12m_1to25_mlx`.
3. **If the base directory ALREADY exists and contains files**: To prevent overwriting your previous run, it appends a timestamp string `_YYYYMMDD_HHMMSS`:
   $$\text{checkpoints/phase\_b\_12m\_1to25\_mlx\_20260808\_234423}$$

### 2. Dynamic Source Selection for Upscaling (in [`notebooks/Training_Suites.ipynb`](file:///Users/ivansamuel/Documents/Projects/telos/notebooks/Training_Suites.ipynb))

When Phase 2 starts and needs to upscale from the 12.5M `1:25` model:
1. `find_latest_checkpoint("phase_b_12m_1to25_mlx")` searches `checkpoints/` for all directories matching `phase_b_12m_1to25_mlx*`.
2. It sorts them by **last modification time (`mtime`) in descending order**, picking `matching[0]` (the newest folder created).
3. It extracts `model.safetensors` from that newest folder and passes it to `load_upscaled_weights(...)`.

This guarantees that upscaling automatically picks the latest trained weights from tonight's run rather than a stale checkpoint from earlier today!
