### Cross-Platform & Hardware Audit Summary

A comprehensive portability audit was conducted across **Windows**, **Linux**, **NVIDIA CUDA**, and **Google Cloud TPU (PyTorch-XLA)**. Below are the verified failure points and the applied solutions.

---

### Technical Findings & Evidence

1. **Windows Portability**:
   - **`signal.SIGKILL` Missing**: On Windows, `signal.SIGKILL` does not exist (`AttributeError`). In [executor.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/eval/executor.py#L197), this caused sandbox exit-code checking to crash. Replaced with `sigkill = getattr(signal, "SIGKILL", 9)`.
   - **Windows Binary Executable Extensions**: In [polyglot_eval.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/eval/polyglot_eval.py#L157), Rust compilation targets lacked `.exe` extensions on Windows, leading to `FileNotFoundError` during execution. Updated binary path to `solution_bin.exe` on `win32`.
   - **Default Codepage (`cp1252`)**: Opening JSON or code files without explicit encoding on Windows raises `UnicodeDecodeError`. Added explicit `encoding="utf-8"` across [probes.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/eval/probes.py#L153), [polyglot_eval.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/eval/polyglot_eval.py#L126), [builder.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/configs/builder.py#L92), [prepare.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/dataprep/prepare.py#L210), [runner.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/eval/runner.py#L69), [trainer_pytorch.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/training/trainer_pytorch.py#L637), and [trainer_mlx.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/training/trainer_mlx.py#L339).
   - **POSIX-Only `fcntl`**: In [bridge.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/afm/bridge.py#L64), `import fcntl` failed on Windows with `ModuleNotFoundError`. Added a `platform.system() != "Darwin"` early exit.

2. **Linux & Headless Server Portability**:
   - **`sysctl` Subprocess Overhead & Failures**: On Linux or Windows, invoking `sysctl` spawned failing processes. In [core.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/training/core.py#L28) and [availability.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/afm/availability.py#L110), guarded `sysctl` and `xcode-select` strictly behind `platform.system() == "Darwin"`.
   - **Non-Metal Linux Environments**: In [builder.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/configs/builder.py#L29), hardware detection checks `MLX_AVAILABLE` (which tests Metal GPU computation) before assigning the `mlx` backend.

3. **NVIDIA CUDA Compatibility**:
   - **Device Mismatches During Evaluation**: In [runner.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/eval/runner.py#L270), probe evaluation created input tensors on CPU while the model resided on CUDA, raising `RuntimeError: Expected all tensors to be on the same device`. Tensors are now dynamically assigned to the model's device (`dev = next(model.parameters()).device`).
   - **Automatic CUDA Device Routing**: In [runner.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/eval/runner.py#L1053), evaluation with `device="auto"` now auto-selects `cuda:0` when CUDA is available.
   - **Iterative Sampler Device Inference**: In [sampler.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/diffusion/sampler.py#L70), `MDLMSampler.sample()` now auto-inherits the active device of the PyTorch model and transfers `prompt_ids` to that device.

4. **Google Cloud TPU (PyTorch-XLA) Compatibility**:
   - **Single-Initialization Guarantees**: [xla_utils.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/training/xla_utils.py) caches device and SPMD topology singletons to prevent `InitializeComputationClient()` duplicate assertion failures across multi-phase runs.
   - **Distributed Synchronization**: [trainer_pytorch.py](file:///Users/ivansamuel/Documents/Projects/telos/telos/training/trainer_pytorch.py) utilizes device-resident static Beta buffers, `xm.reduce_gradients()`, `xm.mark_step()`, and `xm.rendezvous()` to prevent TPU worker desynchronization.
