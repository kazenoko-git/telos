# Télos v1.5.5 Colab TPU retry

Runtime: Colab TPU v5e-1, one XLA worker; Python 3.13.18, PyTorch 2.8.0+cu128, torch-xla 2.8.1, telos-ml 1.5.5.

Each resume comparison ran four training steps uninterrupted and compared its final model weights against a separate run restored from the full-state step-2 checkpoint. All six final model comparisons matched exactly.

| Path | Max absolute weight delta | Exact match |
| --- | ---: | --- |
| AR pretraining | 0.0 | Yes |
| MDLM pretraining | 0.0 | Yes |
| UNDLM pretraining | 0.0 | Yes |
| COROSred pretraining | 0.0 | Yes |
| SFT post-training | 0.0 | Yes |
| DPO post-training | 0.0 | Yes |

SFT and DPO exercised the v1.5.5 XLA training worker, optimizer/RNG/sampler checkpoint, resume, and final model export on the TPU. To run on this one-worker Colab shape, the test directly dispatched the worker because the normal `torch_xla.launch` path failed before training: the PJRT slice builder expected four worker addresses but received one. The default launcher integration therefore remains unverified on this runtime and needs a follow-up fix before claiming the standard v1.5.5 SFT/DPO launch path works on Colab v5e-1.

These were small synthetic smoke runs, not a scale or convergence evaluation.
